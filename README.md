# 🛰️ LogiTrack PRO — Информационная система диспетчеризации и анализа путевых листов

**LogiTrack PRO** — это высокопроизводительное веб-приложение в формате **Single Page Application (SPA)**, разработанное для автоматизации оперативного учета, фильтрации, сортировки и анализа путевых листов (транспортных рейсов) в логистических и торговых компаниях.

---

## 📊 Бизнес-обоснование и экономическая эффективность

Система разработана как замена устаревшим монолитным интерфейсам (Django Templates / HTML Forms) с целью оптимизации рабочего места диспетчера логистики.

1. **Экономия времени сотрудников (Эффект SPA)**: В традиционных системах любой клик по фильтру вызывает перезагрузку страницы (2.5–4 сек). Благодаря SPA-архитектуре (React + DRF) обновление данных происходит асинхронно без перезагрузки вкладки за **150–300 мс**. При 500 операциях в день это экономит **до 25 минут рабочего времени сотрудника ежедневно**. Для отдела из 20 операторов высвобождается **160 человеко-часов в месяц** (эквивалент 1 штатной единицы).
2. **Отказоустойчивость и снижение трафика (Server-side Pagination)**: Вместо выгрузки сотен тысяч строк в браузер (что приводит к зависанию ПК), пагинация и фильтрация выполняются строго на стороне СУБД PostgreSQL. Сервер отдает в сеть **строго 10 строк** (несколько килобайт вместо мегабайт трафика). Нагрузка на корпоративную сеть снижается на **99%**, система работает стабильно даже на слабых офисных ПК.
3. **Рост прибыли**: Скорость формирования путевых листов увеличивается на **20%**, сокращая простои транспорта в утренний пик и повышая пропускную способность склада.

## 🚀 Быстрый запуск проекта локально (одной командой)

Для локального запуска всей инфраструктуры (PostgreSQL + Django + Nginx + React) в изолированных контейнерах вам понадобится установленный **Docker** и **Docker Compose**.

### Шаги запуска

1. **Клонируйте репозиторий проекта на свой компьютер:**
   ```
   git clone https://github.com/AlexanderKokorinV/LogiTrack_SPA_Service
   cd LogiTrack_SPA_Service
   ```

2. **Создайте локальный файл окружения из шаблона:**
   ```
   cp .env.example .env
   ```
   Файл `.env` должен обладать следующей структурой:

   ```
   SECRET_KEY=my_secret_key  # Замените на ваш секретный ключ Django
   DEBUG=True                # Режим отладки

   # Конфигурация базы данных
   DB_NAME=my_data_base      # Имя базы данных
   DB_USER=username          # Имя пользователя (например, postgres)
   DB_PASSWORD=password      # Пароль базы данных
   DB_HOST=db                # Хост базы данных (сервис docker-compose)
   DB_PORT=5432              # Порт, используемый PostgreSQL по умолчанию

   # Настройка разрешенных адресов (Origins)
   CORS_ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
   CSRF_TRUSTED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
   ```

3. **Запустите проект командой (One-command deploy):**
   ```
   # Linux / macOS
   sudo docker compose up -d --build

   # Windows (без sudo)
   docker compose up -d --build
   ```

   **Что Docker выполнит автоматически при этой команде:**
   * Инициализирует изолированную базу данных PostgreSQL и проверит её готовность (`healthcheck`).
   * Запустит Python-контейнер Django, сам проверит наличие новых моделей, выполнит `makemigrations` и применит `migrate` к СУБД.
   * Триггер в `apps.py` обнаружит пустую базу и автоматически сгенерирует 120 путевых листов для демонстрации.
   * Соберет и подготовит статические файлы админки через `collectstatic`.
   * Запустит веб-сервер Nginx на стандартном **80-м порту**, который начнет раздавать React SPA и проксировать запросы к API.

   *При самом первом запуске база данных автоматически наполнится 120 случайными логистическими маршрутами.*

4. **Проверьте работу:** откройте браузер и перейдите по адресу `http://localhost:80` (или `http://localhost`).

**Мониторинг запущенных контейнеров:**
```
sudo docker compose ps
```

**Остановка всей системы:**
```
sudo docker compose down
```

## 🔄 Настройка CI/CD автоматизации (GitHub Actions)

В проекте настроен непрерывный конвейер интеграции и деплоя (CI/CD) через GitHub Actions (`.github/workflows/deploy.yml`). При каждом `git push` в ветку `main` запускается цепочка из трех стадий:

1. **Проверка кода (Lint):** Стиль кода автоматически сканируется линтером `Flake8` на соответствие стандартам PEP 8.
2. **Тестирование (Test):** Разворачивается тестовое окружение на базе Python 3.14, прогоняется весь пакет модульных тестов Django и замеряется покрытие.
3. **Деплой (Deploy):** В случае успеха GitHub Actions подключается к серверу Yandex Cloud по SSH, собирает Docker-образы, обновляет статику, применяет миграции СУБД и обновляет файлы конфигурации `.env`.

### Как настроить автоматический деплой для своего сервера

Для активации конвейера деплоя перейдите в настройки репозитория на сайте GitHub: **Settings** -> **Secrets and variables** -> **Actions** -> **New repository secret** и добавьте следующие секреты:

*   `SERVER_HOST` — Публичный IP-адрес виртуальной машины в Yandex Cloud.
*   `SERVER_USER` — Имя пользователя на удаленном сервере.
*   `SSH_PRIVATE_KEY` — Содержимое вашего секретного приватного ключа доступа.
*   `ENV_FILE` — Содержимое файла настроек `.env`.

## 🛠️ Технологический стек

* **Backend**: Python 3.14, Django 5.2+, Django REST Framework (DRF), Django ORM.
* **Database**: PostgreSQL 16 (хранение данных).
* **Frontend**: React 18, Axios (сетевые запросы), Bootstrap 5 (адаптивная верстка).
* **DevOps & Proxy**: Docker, Docker Compose, Nginx (реверс-прокси и раздача статики SPA), Gunicorn (WSGI-сервер).
* **Testing**: Django APITestCase, Coverage (покрытие тестами **94%**).

## 📂 Структура проекта

```
LogiTrack_SPA_Service/
│
├── backend/                    # Django-приложение (Бэкенд)
│   ├── apps.py                 # Конфигурация и скрипт автозаполнения БД при старте
│   ├── models.py               # Модель ShipmentLog (Дата, Маршрут, Количество, Расстояние)
│   ├── serializers.py          # Сериализатор данных для перевода в JSON
│   ├── pagination.py           # Кастомный класс серверной пагинации (ShipmentlogPagination)
│   ├── views.py                # ViewSet с динамическими ORM-лукапами фильтрации
│   ├── urls.py                 # Изолированная маршрутизация приложения
│   └── tests.py                # Комплексные Unit-тесты бизнес-логики (13 тест-кейсов)
│
├── config/                     # Главный конфигурационный модуль Django
│   ├── settings.py             # Настройки проекта (CORS, Логирование, СУБД)
│   └── urls.py                 # Главный роутер проекта (подключение api/ через include)
│
├── frontend/                   # React-приложение (Фронтенд)
│   ├── src/
│   │   ├── App.js              # Основной компонент SPA-таблицы (логика useState/useEffect)
│   │   ├── index.js            # Точка входа React + внедрение глобального CSS
│   │   └── bootstrap.min.css   # Локальный файл стилей Bootstrap (автономность сборки)
│   └── package.json            # Зависимости фронтенда (Axios, Bootstrap)
│
├── Dockerfile                  # Инструкция сборки Docker-образа для Django (Poetry inside)
├── nginx.conf                  # Конфигурация веб-сервера Nginx (проксирование /api/ и раздача SPA)
├── docker-compose.yml          # Оркестратор контейнеров (db, web, nginx)
├── pyproject.toml              # Файл зависимостей бэкенда (Poetry)
├── .env.example                # Шаблон переменных окружения (фактические секреты хранятся в .env, который в git не коммитится)
└── .github/workflows/deploy.yml # Конвейер CI/CD (Lint → Test → Deploy)
```
